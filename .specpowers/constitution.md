# SpecPowers Constitution
<!-- 项目宪章：声明本项目的核心开发原则。由 /specpowers-init 内联生成 -->

## Core Principles

### I. 质量原则

桥接层定位：不重写 OpenSpec/superpowers 引擎，只编排原生能力。新增能力先判定归属——可判定的文件/状态/git 操作归确定性层（bridge 包），认知引导类内容归 `prompts/` 契约，两者严格分层不越界。

- 关键逻辑行加行前注释；模块/函数 docstring 说明职责与版本演进背景（如「v2.8.0 多活跃需求化」）
- 状态/JSON 写盘一律原子写（临时文件 + rename，复用 `fs_state._atomic_replace` 既有范式）
- 防御式编程：外部输入（JSON、git 输出）读入即校验，损坏时给出恢复引导而非崩溃
- 跨平台同步支持 Windows（cp936 代码页、包装脚本）与 POSIX；脚本对中文 Windows 显式 UTF-8

#### 编码规范

- Python ≥ 3.11 仅标准库，运行时禁止引入 pip 依赖
- 注释与 docstring 用简体中文
- 禁止行尾注释，说明性文字用行前注释
- 函数签名带类型注解（`str | None` 形态）
- 多层嵌套用 Early Return 逐层校验提前返回
- CLI/报错输出必须附可执行的下一步指引（含模型可照抄的命令形态）
- 所有用户输入参数化传递，禁止拼入 shell 命令字符串；git 操作经 `core/git_util.py` 参数列表调用

### II. 测试原则

- 清单/文档/状态机/契约一致性由测试守护：任何清单、契约文案、提示语变更必须同步测试锚点
- 行为变更新增防回潮断言（被移除的旧形态不得回潮，如旧技能名、旧章节标题、封闭枚举）
- 全量测试（tests/ + review 内置自测，当前 361 用例）通过是提交前置
- 测试构造优先模板化 git 仓库，禁止依赖外部网络与真实远程

### III. UX 原则（模型与开发者体验）

- 报错即指引：确定性层报错文案引导正确调用形态（自带子动作词，模型照抄即可零推断重试）
- 破坏性/覆盖性动作（reset/baseline）意图不明必问，不得猜测执行
- 零活跃零噪音：探测/hook 在无活跃需求时零输出，不占用用户注意力
- 确定性层兜底认知层：多活跃未指名的推进类命令拒绝并列出活跃清单与各自阶段

### IV. 性能原则

- SessionStart/UserPromptSubmit hook 亚秒级，任何失败静默退出，绝不阻断用户消息提交
- 技能 description ≤ 25 词（技能列表常驻系统提示的 token 预算）
- 契约分层按需加载：低频细则不预载入执行上下文
- token 消耗是硬指标：写侧禁止复述事实源，读侧局部读取优先（Grep 定位章节/骨架两级读取，命中数与文件规模明显不符时回退全文防静默漏读）

### V. 实现倾向

动手前必须先读本次改动触碰的真实代码与锚点测试，禁止凭猜测实现；是否真的需要此能力（YAGNI）→ 本仓库已有现成范式可复用（原子写/锁/路由表/探测降级）→ Python 标准库已有 → 以上全否，才写当下能工作的最小实现，不做「以后可能用得上」的预留；发现的死代码与陈旧表述即删并加防回潮测试；为绕开阶梯而走的捷径必须记入版本变更说明，不得静默遗留。

## 开发工作流

- 版本升级同步八清单 + pyproject + `__version__` + SKILL.md（版本号一致性由测试自动校验）
- commit message 遵循既有形态：`feat: 中文摘要（①②③ 分点详述），版本升级 vX.Y.Z`
- README/GETTING-STARTED 徽章、安装命令与用例数随版本同步
- 结构一致性门禁（apply 实时三态 + archive 合体后校验）须通过

## 治理

本宪章优先于其他实践约定；所有 PR/code review 须校验是否符合宪章原则（尤其编码规范小节）；修订须记录理由与迁移计划；版本语义化（MAJOR 破坏性 / MINOR 新增原则或实质扩写 / PATCH 措辞调整）；破坏性变更必须提供惰性迁移路径与 README 升级须知。
